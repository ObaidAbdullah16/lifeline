# Grant notes (facts and checklist, not a proposal)

> These are facts and a checklist only. Write any proposal yourself, in your own words: NLnet does not
> allow generative AI in proposal writing at all (accessibility needs excepted). Check every date and
> rule on the funder's website before relying on it.

## Read this first: AI-generated code

Lifeline's first versions were written with an AI coding assistant (see "How this project was built" in
the README). Funders are starting to treat this as an eligibility question:

- **NLnet** published GenAI policy 2.0 on 20 October 2026. It applies to every call with a deadline after
  that date (including Restack and CodeSupply). In short: no GenAI for writing proposals; during funded
  work, GenAI is limited to read-only uses (for example scanning for bugs) and fixes are written by
  people; all past and present GenAI use must be disclosed; a proposal must disclose an existing codebase
  that contains a significant amount of AI-generated code; and work that is "(mostly) generated by LLMs"
  is not eligible.
- **What that means for Lifeline:** disclose the history honestly, plan grant work you write yourself,
  and ask NLnet whether the project qualifies *before* spending time on an application. It may not.

## Evidence to collect before applying anywhere

- [ ] Public repository with CI green, tagged release `v0.3.0` with signed checksums
- [ ] Lifeline's own score published (GitHub Pages) and the badge in the README
- [ ] A `funding.json` (fundingjson.org) in the repository - FOSS United and FLOSS/fund both use it
- [ ] `lifeline batch` run over ~100 projects, anonymised summary published (blog or docs)
- [ ] Issues or discussions from at least 3 external projects that tried the tool
- [ ] Code you wrote and can explain line by line (and a written history of any AI use)
- [ ] A clear work plan: 3-6 milestones, each with deliverables, hours and cost
- [ ] Budget with an hourly rate you can justify
- [ ] How Lifeline differs from OpenSSF Scorecard, zizmor and similar tools
- [ ] Licence (MIT) and a maintenance plan after the grant

## Talking points (rewrite in your own words)

- Gap: tools grade *how code is built*; nothing grades whether a project's *operations* survive
  an expired domain, a single admin, a hijacked CI tag, deletable backups or vanishing credits.
- Design: zero third-party dependencies, deterministic checks, honest coverage reporting.
- Users: small open-source projects and NGOs without an ops team.
